# 2026-08-11

## loop iteration 3 — 増殖ループは終息するか (issue #1)

### やったこと
- 増殖 × 魔法使いのシナジー懸念を検証し、**懸念を棄却して変更なしで #1 をクローズ**
- 検証を再現可能にするため `sim/probe-proliferate.js` を追加（調整用ツール側）
- `sim/BALANCE.md` に追試結果、`sim/README.md` に使い方を追記

### なぜ / 判断

**測定方法を issue に書いた計画から変えた。** #1 には
`node sim/cli.js metrics --games 800` と書いていたが、これは 49組×800試合＝約39,200試合で
数時間かかるうえ、**AI の増殖発動率が1手番あたり4%しかないので勝率にシグナルが乗らない**。
実際 392試合の A/B では魔法使い +0.018＝誤差範囲だった。

懸念の本体は「維持コストをバッズ収入が上回り、**ループが終わらなくなる**」という*機構*なので、
勝率という遠い指標ではなく **ループ到達回数を直接測る**ことにした。
最初に払える手番で強制発動させる統制条件にすれば、発動率4%の壁も消えて
少ない試行数で決着する（低分散）。

**結果を受けてナーフは見送った。** ループは全キャラ・全試行で有限に終息しており、
「バッズ→魔力」は魔法使いのアイデンティティそのもの。増殖が他より長く回るのは
バグではなく設計どおりの強み、と判断した。

### 計測

`node sim/probe-proliferate.js 60`（n=60/側 = 1キャラ最大120試合）

| キャラ | 発動到達% | 平均ループ数 | 上限(8)到達% |
|---|---|---|---|
| you | 53% | 2.49 | **0.0%** |
| 軍師 | 8% | 1.78 | **0.0%** |
| **魔法使い** | 98% | **4.40** | **0.0%** |
| 巨人 | 28% | 1.91 | **0.0%** |
| 陰陽師 | 94% | 3.98 | **0.0%** |
| ネクロマンサー | 53% | 2.48 | **0.0%** |
| 毒使い | 7% | 1.88 | **0.0%** |

- **上限到達 0.0%**（1,000回超の強制発動すべて）→ ループは必ず維持コスト切れで終息する
- 魔法使い 4.40 vs 他平均 2.42（約1.8倍）だが**有限**
- n=30 でも同じ結論（4.45 vs 2.48、cap 0.0%）＝再現性あり

### 副次的発見（ここが今回の収穫）

1. **陰陽師も長い(3.98)**。陰モードの毎ターン魔力+1が効いている。
   「魔法使いだけの問題」という #1 の前提自体が不正確だった。
2. **軍師(8%)・毒使い(7%)は増殖をほぼ発動できない**。非トークン/非毒スキルへの
   コスト修正(+2/+1)で発動コストが8/7になるため。強さの話ではないが、
   **キャラによって使える/使えないが極端に分かれている**のは設計意図の確認が要る → issue #7

### 積み残し

## loop iteration 4 — シャッフルのプールを全21スキルに統一 (issue #2)

### やったこと
- `Game.tsx` の `onClickShuffle` と `runAIMove` の needsShuffle 経路、`sim/ai.js` の
  防御シャッフルを **プール 8 → 21** に統一
- sim に A/B 用ノブ `s.shufflePoolHeart / shufflePoolCircle` を追加（既存の
  `noLockHeart/Circle` と同じ流儀）

### なぜ / 判断
- 手動シャッフルは **21スキル中13種（毒15-19・増殖20）を永久に引けなかった**。
  スキルを足すたびにこの穴が広がるので、プール幅は1箇所の定数に揃える。
- AI 側も同じ 8 で、しかも**狙っている 12/13（ダブル/トリプルロック）が 8 の外**にある。
  コメントには「防御スキルを引くため」と書いてあるのに、数学的に引けない状態だった。

### 計測

| 検証 | 結果 |
|---|---|
| 直接対決 840試合（7キャラ×60×先後、片側のみ旧プール8） | 修正後 **50.7%** vs 修正前 49.3% ＝ **有意差なし** |
| metrics 392試合（seed 1, 修正前後） | 全指標・全キャラ勝率が **完全に一致** |

**metrics が1ビットも動かなかった**ので原因を追ったところ、AI のシャッフル経路は
`needed > 1` ＝ **同時脅威3つ以上**が前提で、実測 **3,631手番中1回（0.03%）**しか
発火しないと判明（同時脅威2つは 1.27%）。つまりこの分岐はほぼデッドコードで、
プールを直しても AI の挙動は変わりようがなかった。

**したがってこの修正の実効はプレイヤー側にある**（手動シャッフルで全21スキルが引ける）。
AI 強度の改善ではない、と正直に記録しておく。

### 反省
直接対決で 50.7% を見た時点では「誤差の範囲」で片付けかけた。metrics が
**完全一致**という不自然さを追いかけて初めてデッドコードに辿り着いた。
**「差が出ない」ときは、効果が小さいのか経路が通っていないのかを必ず切り分ける。**
